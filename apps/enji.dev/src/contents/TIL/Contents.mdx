    <TIL.ItemTags>
      <TIL.ItemTag>agent</TIL.ItemTag>
      <TIL.ItemTag>eval</TIL.ItemTag>
    </TIL.ItemTags>

    大语言模型生成代码天然存在采样波动。在业务高度敏感的政策解析场景中，`pass@k`（跑 `k` 次只要对一次就算过）会严重高估线上可用性。

    ## Apache POI `SXSSFWorkbook` 导出后务必调用 `dispose()`

    <TIL.ItemTags>
      <TIL.ItemTag>java</TIL.ItemTag>
      <TIL.ItemTag>poi</TIL.ItemTag>
      <TIL.ItemTag>oom</TIL.ItemTag>
    </TIL.ItemTags>

    使用 `SXSSFWorkbook` 流式写入十万行级 Excel 虽然能避免堆内存 OOM，但它会在系统临时目录生成大量 `.xml` 缓存文件。仅仅关闭输出流或调用 `close()` 在部分版本下并不会清理磁盘临时文件：

    <TIL.DnD>
      <TIL.Dont>
        ```java {copy:false} {footer:false}
        try (SXSSFWorkbook wb = new SXSSFWorkbook(500)) {
          writeRows(wb);
          wb.write(outputStream);
        }
        ```
      </TIL.Dont>
      <TIL.Do>
        ```java {copy:false} {footer:false}
        SXSSFWorkbook wb = new SXSSFWorkbook(500);
        try {
          writeRows(wb);
          wb.write(outputStream);
        } finally {
          wb.dispose(); // 显式清理磁盘临时刷写文件
          wb.close();
        }
        ```
      </TIL.Do>
    </TIL.DnD>

    ## RabbitMQ 死信队列（DLX）与延迟交换机插件的选型差异

    <TIL.ItemTags>
      <TIL.ItemTag>rabbitmq</TIL.ItemTag>
      <TIL.ItemTag>architecture</TIL.ItemTag>
    </TIL.ItemTags>

    如果队列中同时混入不同 TTL 的消息，基于普通队列 TTL + 死信交换机（DLX）的方案只会检查队首消息是否过期，从而引发严重的**队头阻塞**（短延时消息被长延时消息堵在后面）。

    在停车订单超时自动关单等存在多档超时时间的场景下，应使用 `rabbitmq_delayed_message_exchange`（`x-delayed-message`）插件，在交换机层暂存并按实际到期时间投递。

    ## MySQL 复合索引遇到范围查询后的列无法继续用于索引检索

    <TIL.ItemTags>
      <TIL.ItemTag>mysql</TIL.ItemTag>
      <TIL.ItemTag>innodb</TIL.ItemTag>
    </TIL.ItemTags>

    针对停车订单表常见查询条件 `park_id = ? AND create_time >= ? AND order_status = ?` 建立联合索引时，应将等值过滤列前置：

    ```sql {copy:false} {footer:false}
    -- 推荐：等值列在前，范围列在后，充分利用索引下推与覆盖
    CREATE INDEX idx_park_status_time
      ON parking_order (park_id, order_status, create_time);
    ```

    若写成 `(park_id, create_time, order_status)`，在 `create_time` 发生范围扫描后，`order_status` 将无法再参与 B+ 树快速定位。
