## 业务背景与痛点分析

在机票优惠政策日常运营中，各大航空公司及业务拓展（BD）团队长期通过微信、邮件、钉钉等分散渠道向运营传递政策文档。原有的线下半手工协作模式面临四大突出瓶颈：

1. **政策获取不可见**：多渠道散落导致政策漏收、重复处理，缺乏统一台账。
2. **投放进度不可追踪**：从收到文档到解析、验舱验价、审核及最终上线横跨多个角色，卡点难以实时定位。
3. **处理时效不可衡量**：各环节缺乏标准化耗时统计，单份机票政策端到端投放往往超过 **72 小时**。
4. **到期无法主动预警**：存量政策临近失效缺乏自动巡检提醒，影响运价连续性。

为此，我协同引擎及导购团队共同建设 **“收—投—跟—评—追”** 一体化管理体系，实现机票政策全生命周期线上化与自动化流转。

## 技术架构概览

系统基于阿里分布式技术体系构建：**PandoraBoot + MySQL + TDDL + Tair + MyBatis-Plus + MetaQ + Schedulex + Flowable**。

- **流程编排层**：采用 **Flowable** 工作流引擎统一驱动多节点状态流转与异常补偿；
- **规则计算层**：基于 **正则表达式 + Groovy 动态脚本** 实现可配置化政策抽取与标准模型转换；
- **数据与调度层**：依托 **MySQL + TDDL** 分库分表存储全量生命周期单据，**Tair** 承载热点状态缓存，**Schedulex** 负责政策到期主动巡检与预警任务；
- **异步通信层**：通过 **MetaQ** 消息中间件解耦长耗时节点，平滑串联自动化与人工 SOP。

## 核心职责与工程攻坚

### 1. Flowable 全流程线上化编排

引入 Flowable 工作流引擎，对 **政策接收、自动解析、验舱验价、人工审核、正式投放及到期追踪** 等核心节点进行标准化建模与编排：

- 实现多渠道政策任务统一入池流转与全链路状态实时可观测；
- 针对验价失败、字段校验异常等分支设计清晰的重试与人工兜底闭环，大幅提升运营协同效率。

### 2. “正则提取 + Groovy 转换”解析规则平台化

针对不同航司文件版式与优惠计算逻辑差异较大的难题，设计两段式可配置解析架构：

- **结构化特征提取**：通过可配置正则表达式精准提取原始文本与表格中的关键业务片段；
- **动态脚本清洗转换**：利用 **Groovy 脚本** 动态执行复杂数据清洗、舱位扣率计算及飞猪标准投放模型映射。

该方案无需频繁重启发布主应用即可快速接入新增航司政策格式，上线后平台化规则解析正确率稳定达到 **80% 以上**。

### 3. 大数据量笛卡尔积防 OOM 深度优化

在“单程政策转往返组合”场景中，去程与回程航线集合叠加多舱位、多日期区间会产生巨大的**航线笛卡尔积**，传统全量内存计算加一次性生成 Excel 极易引发 JVM 堆内存溢出（OOM）。

我们从计算与写出两端联合治理：

- **航线分片与增量计算**：按航线批次切片展开组合并前置剪枝无效配对，严格控制单批次驻留内存的数据规模；
- **滑动窗口流式落盘**：使用 Apache POI `SXSSFWorkbook` 替代传统 DOM 模式，将已生成的标准行流式刷写至磁盘临时文件，避免全量数据驻留堆内存，彻底保障大文件及高组合量场景下的服务稳定性。

### 4. 无侵入异步自动化投放建设

存量人工投放 SOP 包含大量经过长期验证的核心校验逻辑，若推倒重写不仅周期长且线上风险极高。

我们在**不改造原有人工 SOP 核心代码**的前提下：

- 向上抽象并复用解析、验舱验价、正式投放等既有领域服务能力；
- 通过 **MetaQ 消息驱动** 方式异步串联各核心执行节点，既实现了人工审核流程与全自动流水线的平滑融合，又彻底规避了长流程同步调用带来的业务线程占用与状态阻塞问题。
